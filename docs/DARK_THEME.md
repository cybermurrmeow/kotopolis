# Светлая и тёмная тема

Переключатель в правом нижнем углу добавлен через общий `base.html`. Луна включает тёмную тему, солнце возвращает светлую. Кнопка доступна с клавиатуры и имеет актуальную подпись для скринридера.

`static/js/theme.js` хранит `light` или `dark` в localStorage под ключом `kotopolis-theme`. Без сохранённого выбора используется светлая тема, независимо от настроек ОС. Синхронное подключение в начале head применяет выбор до загрузки стилей. Если хранилище недоступно, переключение работает на текущей странице, но не обещает сохранение после её закрытия.

Палитра находится в `static/css/theme.css`. Корневые атрибуты `data-theme` и `data-bs-theme` согласуют собственные компоненты и Bootstrap. В существующих стилях цвета получили переменные с прежними значениями в fallback. Светлая тема не определяет новую палитру, поэтому использует исходные цвета. Размеры, анимации, порядок правил и изображения не изменены. Фильтр применяется только к двум служебным иконкам Bootstrap, не к фотографиям или GIF.

Кнопка не участвует в потоке документа, учитывает safe-area и скрывается при печати. При открытом Bootstrap modal она скрыта, чтобы не конкурировать с окном и его фокусом.

## Проверка

```text
python -m pytest -q
python checks/browser_smoke.py --output browser-results
python checks/theme_smoke.py --output theme-results
```

Браузерные проверки требуют `requirements-browser.txt` и установленного Chromium для Playwright. Они используют синтетические аккаунты и временную SQLite, не production. `theme_smoke.py` дополнительно проверяет обе темы на 1440 и 390 px, навигацию, повторное открытие, keyboard, недоступное хранилище, некорректное значение, вкладки, модальное окно и прокрутку. Тестовый маршрут ошибки 500 регистрируется только внутри процесса проверки, не в приложении.

## Известные ограничения

- Стандартные технические HTML-ответы Werkzeug, например 403, не наследуют base.html. Они оставлены без изменений. Для их темизации нужен отдельный согласованный этап обработки ошибок.
- В исходной версии подложка createUserModal перекрывает клики по окну. Проверка фиксирует hit target, сравнение с baseline воспроизводит ту же проблему. Закрытие через Escape работает. Изменение слоёв модального окна не включено в эту задачу, поскольку меняет исходное поведение светлой темы.
- Скриншоты и проверка цветов не заменяют полный WCAG-аудит. Проверки выполнены в Chromium; Safari/Firefox и реальные мобильные устройства отдельно не проверялись.
