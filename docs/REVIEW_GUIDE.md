# Руководство для независимого ревьюера

## Архитектура и границы

Flask-приложение и расширения инициализируются в `app.py`. `models.py` владеет схемой и отношениями ORM, `forms.py` проверяет входные значения, `media.py` проверяет файлы и строит превью, `passwords.py` содержит общую политику пароля, `utils.py` строит экспорт. `daily_story.py` выбирает историю дня и хранит только вспомогательное состояние в файле. `story_bank.py` содержит редакционные тексты по имени котика, а не по зависящему от БД ID.

Приложение пока не использует factory и Blueprints. Это осознанная граница текущего исправления: перенос глобальных extensions и всех маршрутов одновременно усложнил бы проверку бизнес-изменений. Монолит остаётся техническим долгом, а не рекомендованной архитектурой большого приложения. Документ не оправдывает этот долг; он позволяет проверить его отдельно.

Связи: User -> FavoriteCat -> Cat; User -> AdoptionRequest -> Cat; User -> CatComment -> Cat. Сам комментарий может ссылаться на родительский комментарий. GuestUser не является строкой users и имеет только права чтения. Доступ к административным маршрутам проверяется сервером, а не видимостью кнопок.

## Безопасность тестов

`pytest` не выбирает БД из пользовательских переменных. Фикстура перед импортом app принудительно задаёт SQLite в памяти и перед `create_all` проверяет actual engine. Очистка использует только захваченный и проверенный SQLite engine через metadata.drop_all, а не db.drop_all, способный затронуть другие binds. Flask-контекст не живёт между запросами, поэтому два test-client имеют разные сессии. Foreign keys включены; файлы и состояние истории направлены в tmp_path. Конфигурация восстанавливается после каждого теста.

`checks/postgres_review.py` принимает только REVIEW_POSTGRES_URL: localhost/127.0.0.1/::1, PostgreSQL, имя БД заканчивается на `_review`, query options запрещены. Создаётся уникальная схема, миграции и проверки исполняются внутри неё, затем удаляется ровно эта схема. Инструмент не подтверждает работоспособность остальных бизнес-маршрутов на PostgreSQL.

Для этой проверки указывайте драйвер явно: проект использует `psycopg2-binary` из `requirements.txt`.

Пример `REVIEW_POSTGRES_URL` для отдельной локальной тестовой БД:

```text
postgresql+psycopg2://review:YOUR_TEST_PASSWORD@127.0.0.1:55432/kotopolis_review
```

`YOUR_TEST_PASSWORD` здесь заглушка. Подставьте пароль только своей тестовой БД локально, не сохраняйте его в Git. Специальные символы в пароле нужно URL-кодировать. Порт замените на порт своего тестового экземпляра. Адрес без `+psycopg2` может выбрать другой драйвер, которого нет в зависимостях проекта. Не используйте рабочую БД.

## Миграции

1. 713e4cad75bd создаёт исходную схему для пустой БД.
2. b78b1f412a0c проверяет существование и тип must_change_password. Существующие TRUE не теряются, NULL заменяются FALSE, вводятся NOT NULL/default FALSE. Произвольный тип отклоняется. Старые роли переводятся в user без удаления аккаунтов.
3. c12ea302f004 проверяет исторические конфликты и создаёт частичные unique indexes: одна активная заявка на user/cat и одна одобренная на cat.
4. d02f042bae17 проверяет исторические коллизии имён и создаёт unique index lower(username), согласованный с серверной проверкой логина. Исторические коллизии не исправляются молча.

Для unmanaged БД stamp допустим только после проверки соответствия baseline. Ревизия 2 необратима автоматически: нельзя восстановить исходные роли или узнать, существовала ли колонка до миграции. Ревизию 3 можно отменить без удаления данных. Offline SQL для ревизии 2/3 не поддерживается из-за preflight-инспекции.

## История и удаление

Заявки сохраняются, включая отклонённые и отменённые. Legacy delete endpoint возвращает сообщение, а не удаляет запись. Пользователь или котик с заявкой/комментарием не удаляется. Удаление пустой карточки/аккаунта сохраняет прежнюю семантику избранного. Destructive ORM-каскады исторических записей удалены. Ограничения foreign key служат дополнительной защитой, но эти тесты не заменяют проверку PostgreSQL.

Это политика технической сохранности истории. Она не реализует сроки хранения, обезличивание или юридическую процедуру удаления персональных данных. Такие операции должны быть отдельным требованием с тестами, а не побочным эффектом кнопки.

## Сессии и письма

Ссылка reset строится от PUBLIC_BASE_URL. Host/X-Forwarded-Host не формируют origin письма. В cookie хранится digest версии password hash. Изменение пароля делает другие сессии недействительными; текущая сессия смены пароля получает новую версию. Сам hash пароля в cookie не записывается. Это не серверный список всех сессий и не MFA.

Почтовые ошибки возвращают понятный результат отправки; создание аккаунта не объявляет письмо отправленным при выключенном SMTP. Реальный SMTP в ревью не используется. Текущая схема допускает одинаковый email у разных аккаунтов; изменение на unique потребует анализа исторических данных.

## Конкурентность

Создание/одобрение/отмена заявки и редактирование котика используют блокировку строки Cat в PostgreSQL. Индексы защищают от дубликатов даже при гонках. Изменение административных ролей блокирует строки администраторов в последовательном порядке. SQLite не поддерживает эквивалент row locks; прохождение SQLite-тестов не доказывает отсутствие PostgreSQL deadlocks или правильность поведения при нескольких workers.

`python checks/postgres_adoption_concurrency.py` проверяет двойную отправку заявки одним пользователем и одновременное одобрение двух заявок на одного котика. Используется отдельная локальная БД `_review` из `REVIEW_POSTGRES_URL` с явно заданным портом, отличным от 5432. Проверка создаёт и удаляет только свою случайную схему, применяет миграции и вызывает маршруты через два Flask test-client. Пересечение запросов подтверждается цепочкой блокировок PostgreSQL. Сессии синтетические, CSRF отключён. Это не проверка входа, сетевого HTTP-сервера или нагрузки; конкурентная отмена и смена ролей этим инструментом не проверяются.

## Медиа

Проверяется фактический формат, а не только расширение. Ограничения file bytes, pixels и animation frames применяются до построения массива превью; затем кадр уменьшается до промежуточного размера перед RGBA-композицией. PIL/WebP расходуют native memory, поэтому предел пикселей не является точным RSS-лимитом процесса. Для конкурентных загрузок нужны ограниченные workers/ресурсы или отдельная очередь обработки. При ошибке загрузки удаляются только созданные этой загрузкой файлы.

Ссылки принимаются только как HTTPS без credentials, сервер их не скачивает. Локальные пути проверяются на выход из static/upload root. Исторические невалидные или отсутствующие пути получают заглушку в каталоге.

## CSS, HTML и JS

Порядок style.css -> cat-natural.css -> kotopolis-v2.css -> daily-story.css сохранён. Удалены лишь идентичные повторные top-level CSS-блоки с доказанным совпадением селектора и деклараций; разные responsive/override-правила не считаются автоматически мёртвыми. Основной CSS остаётся крупным и требует отдельного последующего рефакторинга с визуальными тестами.

`catalog-hero-v2.js` был не подключён ни одним шаблоном, а его DOM-селекторы отсутствовали. Он удалён. Старые Python-генераторы сцен истории не вызывались build_story или другим модулем и тоже удалены. Legacy URL `/favorite_cat` и `/confirm_email/<token>` сохранены как совместимость возможных старых ссылок: отсутствие внутренних ссылок не доказывает отсутствие внешних клиентов.

AJAX избранного больше не подменяет глобальный window.fetch. Ошибка выводится в aria-live, кнопка блокируется на время своего запроса; страница избранного после удаления обновляет счётчик и пустое состояние. Основная функциональность доступна обычными POST-формами без JavaScript.

## Фактические границы проверки

Общий прогон исправлений: Windows, Python 3.14, 99 тестов на SQLite в памяти. В Chromium прошли 35 основных браузерных проверок, а также 108 проверок страниц и 32 сценария обеих тем. В Chromium и WebKit прошли 220 проверок вёрстки с ширинами 320-430 и 1440 px. Дополнительно прошли 340 проверок обеих тем на 390x844, 844x390, 768x1024, 1024x768 и 1920x1080. Есть браузерные сценарии с включённым CSRF. Python 3.11+ заявлен по синтаксису и зависимостям, но другие версии отдельно не запускались.

На отдельном временном PostgreSQL 18.6 проверены миграции с существующей и отсутствующей колонкой must_change_password, двойная отправка и одновременное одобрение заявок. Рабочие базы не использовались. Это не полный функциональный прогон на PostgreSQL и не нагрузочный тест. Firefox установлен, но не запустился в среде проверки Windows с ошибкой `spawn UNKNOWN`, поэтому результаты для него не заявлены. Реальный SMTP, Safari на устройствах, Redis, все лицензии ресурсов и совместимость со всеми существующими GIF этим прогоном не проверены. Автотесты проверяют сценарии и часть крайних случаев; line coverage не доказывает качество проверки.
