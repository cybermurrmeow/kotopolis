# Устройство проекта и проверки

## Основные части

В `app.py` создаются Flask-приложение и расширения, там же находятся маршруты. Модели вынесены в `models.py`, формы в `forms.py`, обработка изображений в `media.py`, правила пароля в `passwords.py`, экспорт в `utils.py`. `daily_story.py` выбирает котика дня, а тексты берёт из `story_bank.py` по имени, а не по ID записи.

`app.py` пока большой, без фабрики приложения и Blueprints. Если маршрутов станет больше, их стоит разделить по разделам сайта. Сейчас они оставлены вместе, чтобы не совмещать перенос кода с исправлением ошибок.

Пользователь связан с котиками через избранное, заявки и комментарии. Комментарий может быть ответом на другой комментарий. Гостевой вход не создаёт пользователя в БД и разрешает только просмотр. Права администратора проверяются в маршрутах, даже если кнопка скрыта в шаблоне.

## Безопасность тестов

`pytest` всегда использует SQLite в памяти, независимо от `DATABASE_URL`. Фикстура задаёт адрес до импорта приложения и проверяет подключение перед созданием таблиц. Очистка вызывается только для этого подключения через `metadata.drop_all`. Между запросами нет общего Flask-контекста, поэтому клиенты не делят сессию БД. Внешние ключи включены, файлы и история дня сохраняются во временную папку. После теста конфигурация восстанавливается.

`checks/postgres_review.py` берёт адрес из `REVIEW_POSTGRES_URL`. Разрешены только PostgreSQL на localhost/127.0.0.1/::1 и имя БД с суффиксом `_review`, без параметров в URL. Проверка создаёт случайную схему, применяет в ней миграции и затем удаляет эту схему. Остальные таблицы она не меняет. Маршруты приложения этот скрипт не проверяет.

Для этой проверки указывайте драйвер явно: проект использует `psycopg2-binary` из `requirements.txt`.

Пример `REVIEW_POSTGRES_URL` для отдельной локальной тестовой БД:

```text
postgresql+psycopg2://review:YOUR_TEST_PASSWORD@127.0.0.1:55432/kotopolis_review
```

`YOUR_TEST_PASSWORD` здесь заглушка. Подставьте пароль только своей тестовой БД локально, не сохраняйте его в Git. Специальные символы в пароле нужно URL-кодировать. Порт замените на порт своего тестового экземпляра. Адрес без `+psycopg2` может выбрать другой драйвер, которого нет в зависимостях проекта. Не используйте рабочую БД.

## Миграции

1. 713e4cad75bd создаёт исходную схему для пустой БД.
2. b78b1f412a0c проверяет существование и тип must_change_password. Существующие TRUE не теряются, NULL заменяются FALSE, вводятся NOT NULL/default FALSE. Произвольный тип отклоняется. Старые роли переводятся в user без удаления аккаунтов.
3. c12ea302f004 проверяет исторические конфликты и создаёт частичные unique indexes: одна активная заявка на user/cat и одна одобренная на cat.
4. d02f042bae17 проверяет исторические коллизии имён и создаёт unique index lower(username), согласованный с серверной проверкой логина. Исторические коллизии не исправляются молча.

Если база создана без миграций, перед `stamp` нужно сравнить её схему с первой ревизией. Вторую ревизию нельзя автоматически откатить: прежние роли не сохраняются, а происхождение колонки после миграции неизвестно. Третью ревизию можно откатить без удаления данных. Вторая и третья ревизии требуют подключения к БД, генерация SQL без подключения для них не поддерживается.

## История и удаление

Отклонённые и отменённые заявки остаются в базе. Старый маршрут удаления заявки показывает сообщение, но не удаляет запись. Котика или пользователя с заявками и комментариями удалить нельзя. Если истории нет, удаление также убирает связанные записи избранного. Ограничения внешних ключей дополнительно защищают историю от удаления.

Сроки хранения и обезличивание персональных данных пока не реализованы.

## Сессии и письма

Ссылка сброса пароля строится из `PUBLIC_BASE_URL`, а не заголовков Host/X-Forwarded-Host. В cookie хранится отдельный хеш версии пароля, не сам хеш пароля из БД. После смены пароля остальные сессии перестают действовать, а текущая получает новую версию. Отдельного списка активных сессий и двухфакторной авторизации нет.

Если SMTP не настроен или отправка завершилась ошибкой, приложение не сообщает, что письмо отправлено. В журнал записывается тип ошибки, без содержимого исключения и адреса получателя. Ошибки БД также записываются без SQL-параметров. Одинаковый email у разных аккаунтов пока разрешён: перед добавлением уникальности нужно проверить старые данные.

## Конкурентность

При создании, одобрении и отмене заявки, а также при редактировании котика PostgreSQL блокирует строку этого котика. Уникальные индексы не допускают повторных активных заявок и двух одобренных заявок на одного котика. При смене ролей строки администраторов блокируются в одинаковом порядке. В SQLite таких блокировок строк нет, поэтому для одновременных запросов нужна отдельная проверка PostgreSQL.

`python checks/postgres_adoption_concurrency.py` проверяет двойную отправку заявки одним пользователем и одновременное одобрение двух заявок на одного котика. Используется отдельная локальная БД `_review` из `REVIEW_POSTGRES_URL` с явно заданным портом, отличным от 5432. Проверка создаёт и удаляет только свою случайную схему, применяет миграции и вызывает маршруты через два Flask test-client. Пересечение запросов подтверждается цепочкой блокировок PostgreSQL. Сессии синтетические, CSRF отключён. Это не проверка входа, сетевого HTTP-сервера или нагрузки; конкурентная отмена и смена ролей этим инструментом не проверяются.

## Медиа

Перед созданием превью проверяются формат файла, его размер, число пикселей и кадров. Каждый кадр сначала уменьшается, затем переводится в RGBA. Ограничение пикселей не задаёт точный предел памяти: Pillow и WebP выделяют память и вне Python. При большом числе одновременных загрузок понадобятся ограничения ресурсов или очередь обработки. При ошибке удаляются только файлы, созданные этой загрузкой.

Внешние ссылки принимаются только по HTTPS без логина и пароля; сервер их не скачивает. Локальный путь должен оставаться внутри разрешённой папки. Если старый путь неверен или файл отсутствует, каталог показывает заглушку.

## CSS, HTML и JS

Порядок подключения стилей сохранён. При чистке удалены только одинаковые повторные блоки CSS; правила для разных размеров экрана оставлены. Основной CSS пока большой, его дальнейшее сокращение нужно проверять по скриншотам.

Неиспользуемый `catalog-hero-v2.js` и старые генераторы историй удалены после проверки подключений и вызовов. Старые URL `/favorite_cat` и `/confirm_email/<token>` оставлены, чтобы не ломать сохранённые ссылки.

Избранное обновляется через отдельный AJAX-запрос, без подмены `window.fetch`. На время запроса кнопка блокируется, ошибка выводится в `aria-live`. После удаления обновляются счётчик и сообщение о пустом списке. Без JavaScript остаются обычные POST-формы.

## Что проверено

Проверки выполнены на Windows с Python 3.14. После правки текстов прошёл 101 тест на SQLite в памяти и 35 основных браузерных проверок в Chromium. Ранее при объединении исправлений прошли 108 проверок страниц и 32 сценария обеих тем, 220 мобильных проверок и 340 проверок дополнительных размеров в Chromium/WebKit. Среди них 390x844, 844x390, 768x1024, 1024x768 и 1920x1080. Есть браузерные сценарии с включённым CSRF. Python 3.11+ заявлен по синтаксису и зависимостям, но другие версии отдельно не запускались.

На отдельном временном PostgreSQL 18.6 проверены миграции с существующей и отсутствующей колонкой must_change_password, двойная отправка и одновременное одобрение заявок. Рабочие базы не использовались. Полного функционального и нагрузочного прогона на PostgreSQL не было. Firefox установлен, но не запустился в Windows с ошибкой `spawn UNKNOWN`. Реальный SMTP, Safari на устройствах, Redis, лицензии всех ресурсов и совместимость со всеми существующими GIF не проверены.
